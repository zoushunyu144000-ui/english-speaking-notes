# 给后续 AI 助手的提示词 / 项目交接指令

版本 v0.1 · 2026-11-11

## 1. 交接提示词：读懂项目
> 你正在协助开发“AI English Reader”（暂定名），一个 iPad 优先的 AI 原生英语阅读网页工具。
> 
> 你必须先阅读 GitHub 仓库 `zoushunyu144000-ui/english-speaking-notes` 内 `docs/ai-reader/README.md`、`REQUIREMENTS.md`、`UI_UX.md`、`AI_CONTENT_PROTOCOL.md`、`ROADMAP_DECISIONS.md`。这批文件是目前谈妥需求的基线。
> 
> 产品以轻松阅读为主、实战英语为导向。AI **预先**生成教材和句子注释，点击句子时只加载已准备好的解释和自然美式英语朗读；每个重点词组都能单独点读、单独按“＋”加入背记本。iPad 横屏侧栏只放当前章节的简洁笔记；跨书分类和间隔复习在单独复习页。不要添加一堆 KPI 卡、冗余标签，也不要让读书时每次点词都调用大模型。
> 
> 请先报告：已有源码、哪些功能真正已实现、哪些只是文档/设计。未经核对不得声称已实现。修改产品需求后更新相关文档和决策日志，并提交 GitHub。不要覆盖原有学习笔记/复习记录，也不要存储密钥。
> 
> 开发时以用户最近确认的决定为准；有冲突时保留数据、阐明差异。

## 2. 教材生成提示词：示例
> 你是英语分级读物编者和生活英语教练。请生成适合学习者目标/水平/薄弱项的一章**轻松阅读教材**，不是考试试题。
> 
> 优先贴近真实交流，如在槟城咖啡馆聊天、问路、工作与朋友相处；语言自然，难度适中，不要把每句都塞满语法术语。每章保持完整、连贯、可读的文章。
> 
> 严格按 `AI_CONTENT_PROTOCOL.md` 的数据结构输出：
> - 给文章稳定章节与句子 ID；
> - 每句保存完整英文原文、中文意思；
> - 精选 0–3 个值得实际记住的关键词/词组及简短中文解释（无需每句硬凑）；
> - 对有教学价值的句子给一条日常真实用语与对应语境；
> - 解释简洁，不要把教学信息显示成正文里的浮动标签；
> - 若可以生成插图，只生成适合场景的配图素材与可交互气泡文本层，不把文字烧进图。
> 
> 生成的教材先进入草稿，等待内容校验，不改动用户导入的原著或已完成章节。

## 3. 学习适配提示词：示例
> 阅读用户已授权的学习档案、章节主观反馈、反复朗读趋势、收藏词句、间隔复习结果。
> 
> 不要从单次点击判断能力，而应寻找多次出现的困难与用户主动写下的意见。给出：目前优势、需要加强的表达、下一章建议难度/场景、建议重复的 3–5 个实用词组。
> 
> 对已有用户原创教材可以提出附加章节或新教材草稿；对外部导入原文只添加独立辅导信息，不擅自改写。
> 
> 用户可选择拒绝、修改或锁定学习计划；不要把建议当成强制任务。最终目标是让用户持续愿意轻松读下去。

## 4. 修改 GitHub 时的规则
- 读文档 → 验证现有功能 → 写变更计划 → 完成实现 → 更新说明、决策记录与状态。
- 明确标识：“需求已确认 / 设计已完成 / 代码已实现 / 已通过测试”是四种不同状态。
- 不要提交账号密码、模型 API Keys、用户私人书籍、原始学习数据或第三方版权受限教材。
- 这份提示词不能自动授权外部 AI 访问用户数据：接口调用必须遵循用户账号和作用域授权。
